# Testing Policy

## 원칙
- 성공률은 지원 범위 안에서 측정한다.
- 자동화보다 실기기 수동 검증이 우선이다. 접근성/오버레이는 에뮬레이터만으로 신뢰하기 어렵다.
- 릴리즈 빌드에서 개인정보성 로그를 남기지 않는다.

## 통과 기준
각 지원 명령은 30회 중 27회 이상 성공해야 한다.

성공 조건:
- STT 결과 후 1초 이내 마스킹, 스크롤 안내, 또는 실패 안내가 표시된다.
- 안내된 후보 영역은 실제로 사용자가 누를 수 있다.
- 금지 버튼이 안내되지 않는다.
- 자동 입력 허용 범위 밖의 텍스트를 입력하지 않는다.

## V1 테스트 매트릭스
- 삼성 실기기 1대
- Pixel 계열 또는 에뮬레이터 1대
- 글자 크기 기본/크게
- 삼성 키보드/Gboard

## 필수 시나리오
- 쿠팡: “물티슈 찾아줘”
- 쿠팡: “장바구니 보고 싶어”
- 카카오톡: “아들한테 밥 먹었냐고 보내고 싶어”
- 카카오톡: “사진 보내고 싶어”
- 코레일톡: “예매한 표 보고 싶어”
- 코레일톡: “승차권 예매하고 싶어”

## CLI 검증
Android SDK가 있는 환경:

```bash
./gradlew assembleDebug
```

Windows Android Studio 환경:
- Gradle Sync 성공
- Debug APK 설치 성공
- 접근성 서비스 활성화 후 실기기 시나리오 수행

## 실패 기록
릴리즈 앱에는 자동 로그를 저장하지 않는다. 개발 중 실패는 수동으로 다음 항목만 기록한다.
- 기기/OS
- 앱 버전
- 명령
- 실패 단계
- 후보를 못 찾았는지, 너무 많았는지, 자동 입력 실패인지

화면 텍스트 원문, 음성 원문, 개인정보는 기록하지 않는다.
